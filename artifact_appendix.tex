\subsection{Abstract}

This artifact provides the complete benchmark suite, generation scripts,
pre-generated Verilog outputs, and testbenches for the \textit{HierRTLBench}
paper. The artifact enables reviewers to:
\begin{enumerate}[leftmargin=*, topsep=2pt, itemsep=1pt, parsep=0pt]
  \item \textbf{Validate pre-generated outputs} (no GPU required): run
        \texttt{iverilog} syntax checks on the included Verilog files and
        reproduce the syntax pass-rate table from the paper.
  \item \textbf{Regenerate outputs} (GPU required): re-run VeriGen 2B/6B/16B
        using the provided Python/SLURM scripts and compare against paper
        results.
\end{enumerate}

The benchmark compares two RTL generation strategies---\textit{unified} (one
prompt per module) and \textit{hierarchical} (one prompt per submodule)---across
14 hardware designs of increasing complexity, run through three open-weight
VeriGen model sizes (2B, 6B, 16B parameters).

\noindent\textbf{Minimal requirements for validation path (A):}
any Linux/macOS machine with Python~3.9+ and \texttt{iverilog}, and
$\sim$2~GB disk space.

\noindent\textbf{For full regeneration path (B):}
NVIDIA GPU with $\geq$16~GB VRAM ($\geq$80~GB for the 16B model) and
$\sim$60~GB disk for model weights.

\subsection{Description}

\subsubsection{How to Access}

Clone the repository:
\begin{lstlisting}
git clone https://github.com/yashwant/HierRTLBench.git
cd HierRTLBench
\end{lstlisting}

All generated outputs are already included:
\begin{itemize}
  \item \texttt{vgen\_project/verigen\_out/\{2B,6B,16B\}/} --- hierarchical
        Verilog outputs
  \item \texttt{vgen\_project/unified\_outputs/\{2B,6B,16B\}/} --- unified
        Verilog outputs
  \item \texttt{vgen\_project/verigen\_testbenches/} --- testbenches for all
        14 modules
\end{itemize}

Approximate disk usage after clone: $\sim$500~MB (outputs). Model weights
($\sim$50~GB) are downloaded on demand.

\begin{itemize}
  \item \textbf{Syntax validation:} Any CPU; no GPU required.
  \item \textbf{Full regeneration:} NVIDIA GPU with CUDA~12.x.
    \begin{itemize}
      \item VeriGen-2B: $\geq$16~GB VRAM
      \item VeriGen-6B: $\geq$24~GB VRAM
      \item VeriGen-16B: $\geq$80~GB VRAM (H100 or A100~80~GB recommended)
    \end{itemize}
\end{itemize}

\subsection{Installation}

\textbf{Step 1:} Install system dependencies.
\begin{lstlisting}
# Ubuntu/Debian
sudo apt-get install iverilog python3 python3-pip

# macOS (Homebrew)
brew install icarus-verilog python
\end{lstlisting}

\textbf{Step 2:} Install Python dependencies.
\begin{lstlisting}
pip install -r requirements.txt
# GPU inference: match your CUDA version
pip install torch \
  --index-url https://download.pytorch.org/whl/cu121
\end{lstlisting}

\textbf{Step 3 (HPC only):} Use the provided setup script.
\begin{lstlisting}
bash vgen_project/setup_env.sh
\end{lstlisting}

\noindent\textbf{Smoke test:}
\begin{lstlisting}
iverilog -tnull \
  vgen_project/verigen_out/2B/m01_alu/alu_addsub.v \
  && echo "PASS" || echo "FAIL"

python evaluate_syntax.py --models 2B
\end{lstlisting}
Expected: \texttt{PASS} from \texttt{iverilog}; a pass-rate summary table
from the Python script.

\subsection{Experiment Workflow}

\noindent\textbf{Path A --- Cached-output validation (recommended, no GPU):}
\begin{lstlisting}
python evaluate_syntax.py \
  --hier_dir    vgen_project/verigen_out \
  --unified_dir vgen_project/unified_outputs \
  --tb_dir      vgen_project/verigen_testbenches/\
verigen_testbenches
\end{lstlisting}

\noindent\textbf{Path B --- Full regeneration (GPU required):}
\begin{lstlisting}
# Hierarchical generation (all models)
python vgen_project/verigen_runner.py \
  --model 2B --output_dir /tmp/hier_out
python vgen_project/verigen_runner.py \
  --model 6B --output_dir /tmp/hier_out
python vgen_project/verigen_runner.py \
  --model 16B --output_dir /tmp/hier_out

# Unified generation (all models)
python vgen_project/run_unified_verigen.py \
  --model 2B --output_dir /tmp/unified_out
# ... repeat for 6B and 16B

# Write deterministic integration tops
python vgen_project/write_integrations.py \
  --output_dir /tmp/hier_out

# Evaluate
python evaluate_syntax.py \
  --hier_dir /tmp/hier_out \
  --unified_dir /tmp/unified_out
\end{lstlisting}

\noindent\textbf{Path C --- Bounded subset (single module, fastest):}
\begin{lstlisting}
python vgen_project/verigen_runner.py \
  --model 2B --output_dir /tmp/smoke --idx 0
iverilog -tnull \
  /tmp/smoke/m01_alu/alu_addsub.v \
  && echo "PASS" || echo "FAIL"
\end{lstlisting}

\noindent The convenience wrapper \texttt{run\_evaluation.sh} encapsulates all
paths:
\begin{lstlisting}
bash run_evaluation.sh --cached      # Path A
bash run_evaluation.sh --regen-2b    # Path B, 2B only
bash run_evaluation.sh --full-regen  # Path B, all models
\end{lstlisting}

\subsection{Experiment Customization}

\begin{itemize}
  \item \textbf{Model size:} Pass \texttt{--model 2B/6B/16B} to any runner.
  \item \textbf{Single submodule:} Use \texttt{--idx N} (0--66) in
        \texttt{verigen\_runner.py} for one submodule at a time (used by SLURM
        array jobs).
  \item \textbf{Output directory:} \texttt{--output\_dir /path/to/dir} in all
        scripts.
  \item \textbf{Inference temperature:} Edit \texttt{GEN\_CFG["temperature"]}
        in \texttt{verigen\_runner.py} or \texttt{run\_unified\_verigen.py}.
  \item \textbf{Custom prompts:} Append entries to the \texttt{SUBMODULES}
        list in \texttt{verigen\_runner.py} following the existing format.
\end{itemize}

\subsection{Notes}

\begin{itemize}
  \item SLURM scripts contain HPC-specific paths (e.g.,
        \texttt{/scratch/soumyaj/}). Edit the \texttt{PYTHON} and
        \texttt{HF\_HOME} variables at the top of each script before
        submitting on a different cluster.
  \item VeriGen uses the CodeGen architecture with a hard 2048-token limit.
        Generation stops at this limit even if a module is incomplete; this
        constraint is the central subject of the paper.
  \item Total model weight storage: $\sim$48~GB for all three sizes. Plan
        storage accordingly, especially on HPC home directories.
\end{itemize}
